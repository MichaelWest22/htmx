Full page load — messages pre-populated by server

Full page path: the server drains the flash bag during the page render and writes <drupal-message> children directly into <drupal-messages> in the initial HTML. No htmx, no <hx-partial>, no JS insertion. connectedCallback fires on each <drupal-message> as the browser parses the page and announces them exactly as it would for htmx-delivered messages — the same code path, the same element, the same behaviour.

The <drupal-messages> container is always present in the page template. When there are no messages it is empty and hidden by drupal-messages:empty { display: none }. No fallback element, no hidden placeholder div, no JS promotion dance.
