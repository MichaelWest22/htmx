<drupal-contextual> custom element demo

Approach: each <drupal-contextual> is a light DOM custom element. On page load it is an invisible placeholder carrying its contextual ID as name and HMAC token as value attributes. A single <drupal-contextual-loader> element collects all of them via hx-include and fires one batch GET to /contextual/render. htmx treats custom elements with name/value as form inputs, so no hidden <input> children are needed. The server validates each HMAC token and returns one <hx-partial hx-swap="outerHTML"> per region, each wrapping a fully-rendered <drupal-contextual>. The browser replaces the placeholder element, connectedCallback fires on the new element, and the open/close behaviour is wired — no JS fetch loop, no sessionStorage, no JSON parsing, no manual DOM routing.

On success the server also returns <hx-partial hx-target="drupal-contextual-loader" hx-swap="delete"> which removes the loader and stops polling. On a 5xx the loader stays, retries every 5s, and only re-requests the still-unresolved regions via hx-include="drupal-contextual:not(:has(.trigger))". htmx detects the hyphenated tag name and reads name/value directly off the element — a get value() getter in the class returns the attribute. No hidden <input> children needed.

Batch load — one request, all regions

On page load <drupal-contextual-loader> collects all unresolved placeholders via hx-include="drupal-contextual:not(:has(.trigger))" and fires one GET. Each element's name is the contextual ID and value is its HMAC token — htmx reads them directly off the custom element. The response delivers four <hx-partial hx-swap="outerHTML"> tags plus a delete partial that removes the loader. Each replaced element's connectedCallback wires its open/close behaviour immediately.

Re-render a single region

After an admin action the server returns a single <hx-partial hx-swap="outerHTML"> for just the affected region. The old element is replaced, connectedCallback re-fires on the new one, and the other three regions are untouched.

No links — access denied

When the user has no access the server returns an empty <hx-partial> (default innerHTML swap). The <drupal-contextual> element stays in the DOM but empty, hidden by drupal-contextual:not(:has(.trigger)) { display:none } — no JS needed. It is also excluded from any retry request by hx-include="drupal-contextual:not(:has(.trigger))" since the resolved element has no name attribute.

Full page load with pre-rendered links

When the page is not cached the server renders the trigger button and link list directly into <drupal-contextual> in the initial HTML — no loader element, no GET request. connectedCallback fires as the browser parses each element and wires the behaviour immediately.
