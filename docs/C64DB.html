WHAT IS C64DB?

C64DB is a blazing-fast, dependency-free database that fits in 64K (well, not really, but it feels that way). Inspired by the raw, direct memory access philosophy of the Commodore 64, C64DB lets you PEEK and POKE your data with zero ceremony.

"Why use an ORM when you can POKE directly into memory?"

QUICK START NEW!

LOAD "C64DB",8,1
READY.
import c64db from 'c64db';

const db = c64db.init();

CORE CONCEPTS

PEEK — READING DATA

PEEK(address) reads a single byte from a memory location. In C64DB, PEEK retrieves a record by its address (id). 

// PEEK at address 53280 (border color register -- classic!)
const record = await db.peek(53280);

// PEEK a range of addresses
const records = await db.peekRange(49152, 49162);

Returns null if nothing lives at that address. No exceptions. No drama. Just like the real thing.

POKE — WRITING DATA

POKE(address, value) writes a byte to a memory location. In C64DB, POKE inserts or overwrites a record at the given address. 

// POKE 53280,0  -- classic black border trick
await db.poke(53280, { color: 'black', notes: 'classic demo trick' });

// POKE multiple addresses at once
await db.pokeMany([
  [53280, { color: 'black' }],
  [53281, { color: 'black' }],  // background too
]);
⚠ WARNING: Just like on the real C64, POKEing the wrong address can cause unexpected behaviour. There is no undo. POKE RESPONSIBLY.

SYS — EXECUTING STORED PROCEDURES

SYS(address) jumps to machine code at a memory address. In C64DB, SYS executes a named stored procedure. 

// SYS 64738 -- the famous soft reset address
await db.sys('RESET_USER_SESSIONS', { olderThan: '30d' });

await db.sys('REBUILD_INDEX', { table: 'sprites' });

LOAD — IMPORTING DATA

// LOAD "*",8,1  -- load first program from disk
await db.load('backup_2024.d64', { device: 8, secondary: 1 });

The ,8 refers to device number (your storage backend). The ,1 loads into the address specified in the file header — i.e. it respects your schema.

SUPPORTED DEVICES:

Device # Backend
8 Primary disk (default)
9 Secondary disk
1 Datasette (tape / slow, but reliable)

SAVE — EXPORTING DATA

// SAVE "MYDATA",8
await db.save('MYDATA', { device: 8 });

// SAVE with address range
await db.save('SPRITES', { device: 8, start: 0x2000, end: 0x3FFF });

MEMORY MAP

C64DB reserves certain address ranges, just like the real C64 hardware registers:

Address Range Purpose
0x0000–0x00FF Zero page — ultra-fast key/value cache
0xD000–0xD3FF VIC-II registers — UI/display metadata
0xD400–0xD7FF SID registers — event/audio log
0xC000–0xCFFF Free RAM — your collections live here
0xE000–0xFFFF KERNAL ROM — system tables, read-only
Attempting to POKE into 0xE000–0xFFFF will throw a KERNAL_VIOLATION error.

SPRITES — INDEXED VIEWS

Sprites are lightweight, pre-defined views over your data. Up to 8 sprites can be active at once (hardware limitation). 

// Define a sprite (indexed view)
db.defineSprite(0, {
  name: 'active_users',
  query: { status: 'active' },
  color: 1  // white
});

// Read from sprite
const users = await db.sprite(0).peek();

ERROR HANDLING

C64DB errors follow classic C64 error messages:

Error Code Message Meaning
?SYNTAX ERROR Invalid query syntax You typed something wrong
?OUT OF MEMORY ERROR Storage limit reached Time to SAVE and clear
?ILLEGAL QUANTITY ERROR Value out of range Check your POKE value
?DEVICE NOT PRESENT Backend unreachable Check your connection
?LOAD ERROR Import failed Corrupt or missing file
?BREAK Query cancelled User or timeout interrupted 
try {
  await db.poke(0xFFFF, data);
} catch (e) {
  if (e.code === 'KERNAL_VIOLATION') {
    console.error('?ILLEGAL QUANTITY ERROR IN 10');
  }
}

THE DATASETTE (TAPE) MODE

For environments where disk access is unavailable, C64DB falls back to Datasette mode — slower, sequential reads, but it always works eventually. 

const db = c64db.init({ device: 1 }); // tape mode

// Expect this to take a while...
// PRESS PLAY ON TAPE
await db.load('archive.tap');

CONFIGURATION — POKE THE REGISTERS

Fine-tune C64DB by poking its config registers directly:

c64db.config.poke('BORDER_COLOR', 0);       // 53280 -- cosmetic only
c64db.config.poke('CACHE_SIZE', 256);        // zero page size
c64db.config.poke('MAX_SPRITES', 8);         // concurrent views
c64db.config.poke('TURBO_MODE', true);       // skip validation (dangerous!)
